# ДЗ 4. Интерфейс «ПотребКонсульт»

Основа задания — [ТЗ](../hw3/technical_specification.md), [сравнение трёх концепций](../hw3/ui_concepts/ui_description.md) и [шаблоны запросов](../hw2/prompt_templates.md). Выбрана концепция 3: рядом с ответом видны основания из закона. На телефоне карточка переходит в одну колонку, а длинная выдержка открывается по нажатию.

## Что показать

1. На /demo откройте вопрос про отсутствие чека и раскройте источник [1]. Номер в заголовке соответствует номеру в тексте.
2. Нажмите «Черновик претензии». В текст подставляется описание ситуации. Реквизиты и требование заполняются после копирования.
3. Поставьте оценку «Полезно», затем смените её на «Не помогло». В демонстрации оценка действует до перезагрузки. В личном кабинете изменение сохраняет API.
4. На / войдите в кабинет. Для короткого вопроса кнопка отправки отключена. Пока сервер работает, повторная отправка заблокирована. При ошибке введённый вопрос остаётся в форме.

## Применение AI

Входной запрос автора — «изучить что щас сделано и сделать 4-5 ДЗ». Контекстом для агента послужили готовый проект, правила AGENTS.md и задания из DOCX. Агент выделил критерии сдачи, реализовал React-компоненты и проверил их тестами. Ниже приведены воспроизводимые формулировки по шаблонам ДЗ 2.

| Задача для агента | Проверяемый результат |
|---|---|
| Реализуй карточку по концепции 3. Покажи номер источника, раскрой цитату по нажатию, предусмотрев узкий экран. | AnswerCard используется и в демонстрации, и в рабочем кабинете. |
| Добавь тесты React Testing Library на отказ, оценку и ошибку входа. | Тесты проверяют доступные пользователю надписи, состояния кнопок и сообщение API. |
| Проверь, что шаблон претензии не уходит на сервер. | Черновик формируется в компоненте, кнопка копирования обращается к буферу обмена браузера. |

## Проверка и выводы

Vitest проверяет четыре сценария: источник и черновик, изменение оценки, отказ при отсутствии оснований и ошибку входа. Сборка включает строгую проверку TypeScript. В ходе разработки npm audit указал на устаревшие зависимости, версии были пересмотрены. Для демонстрации достаточно запустить frontend и открыть /demo, для проверки сохранения нужен полный стенд. [Команды запуска](../README.md).

В учебной версии вопрос обрабатывается целиком. Историю предыдущих вопросов модель не получает. Для оценки качества консультаций отдельно нужны проверка правовых выводов экспертом и актуализация корпуса закона.
