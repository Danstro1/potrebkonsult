# ДЗ 2. Система правил и промпт-шаблонов

## Шаг 1. Описание проекта и требований

### Проект

**«ПотребКонсульт»** — веб-приложение с интеллектуальным ассистентом по защите прав потребителей. Пользователь задаёт вопрос своими словами («купил наушники, через неделю сломались, магазин отказывается менять»), а ассистент отвечает простым языком со ссылками на конкретные статьи нормативных документов.

Проект является практической частью магистерской работы «Разработка интеллектуального ассистента по защите прав потребителей на основе больших языковых моделей с применением RAG и дообучения».

Принцип работы — RAG (Retrieval-Augmented Generation):

1. Нормативные документы (Закон РФ «О защите прав потребителей», Правила продажи товаров, перечень технически сложных товаров, Постановление Пленума ВС РФ № 17) нарезаются на фрагменты по статьям и пунктам.
2. Фрагменты переводятся в эмбеддинги и хранятся в векторной базе.
3. По вопросу пользователя находятся релевантные фрагменты.
4. Языковая модель формирует ответ строго на основе найденных фрагментов и указывает источники.

### Технологический стек

| Слой | Технологии |
|---|---|
| Frontend | TypeScript, React 18, Vite, Tailwind CSS, React Router, TanStack Query |
| Backend | Python 3.11, FastAPI, Pydantic v2, SQLAlchemy 2 (async) |
| База данных | PostgreSQL 16 + расширение pgvector (Supabase) |
| Аутентификация | Supabase Auth |
| RAG | эмбеддинги BGE-M3 (sentence-transformers), гибридный поиск (векторный + полнотекстовый), реранкер |
| Языковая модель | локально через Ollama (открытая модель 7–8 млрд параметров, например Qwen); резервно — API OpenRouter / YandexGPT |
| Дообучение (отдельно от приложения) | Hugging Face Transformers, PEFT (LoRA/QLoRA), TRL; запуск в Kaggle/Colab |
| Тесты | Vitest + React Testing Library (frontend), pytest (backend) |
| Инфраструктура | Docker, docker-compose, GitHub Actions |
| Качество кода | ESLint + Prettier (frontend), Ruff + mypy (backend) |

### Архитектура

```
[React SPA] ──HTTP/JSON──> [FastAPI]
                              ├── api/          — роуты, валидация запросов
                              ├── services/     — бизнес-логика (чат, претензии, админка)
                              ├── rag/          — нарезка, эмбеддинги, поиск, сборка промпта
                              ├── llm/          — клиент модели (Ollama / OpenRouter) за общим интерфейсом
                              └── repositories/ — доступ к БД
                                        │
                              [PostgreSQL + pgvector]
```

### Ключевые требования к коду

**Стиль кода**
- Frontend: функциональные компоненты, строгая типизация (`strict: true`), именование компонентов в PascalCase, хуков — `useXxx`, файлов компонентов — `ComponentName.tsx`.
- Backend: PEP 8, аннотации типов везде, Pydantic-модели для всех входных и выходных данных API, docstring для публичных функций.
- Комментарии и пользовательские тексты — на русском, идентификаторы в коде — на английском.

**Архитектура**
- Слоистая структура backend: роут не обращается к БД напрямую, только через сервис.
- Модуль RAG не зависит от FastAPI и может запускаться отдельно (нужно для экспериментов магистерской).
- Клиент языковой модели скрыт за интерфейсом, чтобы локальную модель можно было заменить API без изменения бизнес-логики.

**Стандарты разработки**
- Конфигурация и секреты — только через переменные окружения (`.env`, в репозитории — `.env.example`).
- Коммиты в формате Conventional Commits (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`).
- Для бизнес-логики и модуля RAG обязательны unit-тесты.
- Предметное требование: ассистент никогда не даёт ответ без ссылки хотя бы на один найденный фрагмент документа; если релевантных фрагментов нет — система явно отказывает.
