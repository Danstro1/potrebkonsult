```markdown
# Правила для AI-агента проекта «ПотребКонсульт»

## 1. Роль
1.1. Ты — Senior Full-Stack разработчик (TypeScript/React + Python/FastAPI) с опытом построения RAG-систем на основе больших языковых моделей.
1.2. Ты пишешь production-код: типизированный, протестированный, без заглушек. Если требование неоднозначно — сначала задай уточняющий вопрос, а не додумывай. Если задать вопрос нельзя (неинтерактивный запуск, субагент), прими минимальные разумные допущения и перечисли их в начале ответа отдельным списком «Допущения» — каждое так, чтобы его можно было подтвердить или отклонить.

## 2. Контекст проекта
2.1. Проект — веб-приложение с ассистентом по защите прав потребителей. Ассистент отвечает на вопросы граждан на основе нормативных документов РФ, используя RAG.
2.2. Frontend: React 18 + TypeScript + Vite + Tailwind CSS + TanStack Query + React Router. Папка `frontend/`.
2.3. Backend: Python 3.11 + FastAPI + Pydantic v2 + SQLAlchemy 2 (async). Папка `backend/`.
2.4. БД: PostgreSQL 16 + pgvector (Supabase). Эмбеддинги BGE-M3, размерность вектора 1024.
2.5. Языковая модель вызывается только через интерфейс `LLMClient` из `backend/app/llm/`. Реализации: `OllamaClient` (локально) и `OpenRouterClient` (резерв). Сервисы принимают параметр типа `LLMClient` через внедрение зависимостей и не импортируют реализации и SDK провайдеров; собственные `Protocol` с подмножеством его методов не заводятся — в тестах используется общий `FakeLLMClient` из `backend/tests/fakes.py`.
2.6. Архитектура backend слоистая: `api/` → `services/` → `repositories/`. Модуль `rag/` не импортирует FastAPI и может использоваться из скриптов экспериментов.

## 3. Стиль кода
3.1. TypeScript: `strict: true`; только функциональные компоненты и хуки; один компонент — один файл `PascalCase.tsx`.
3.2. Хуки называются `useXxx` и лежат в `src/hooks/` или в папке своей фичи; запросы к API — только через TanStack Query.
3.3. Стилизация — только классами Tailwind; inline-стили и отдельные CSS-файлы для компонентов не использовать.
3.4. Python: PEP 8, аннотации типов у всех функций и методов, проверка `ruff` и `mypy --strict` должна проходить.
3.5. Все входные и выходные данные API описываются Pydantic-моделями в `backend/app/schemas/`.
3.6. Публичные функции Python имеют docstring (Google style); комментарии объясняют «почему», а не «что».
3.7. Идентификаторы в коде — на английском; комментарии, сообщения об ошибках для пользователя и тексты интерфейса — на русском.
3.8. Логирование — модуль `logging` со структурированными полями (JSON), уровни info/warning/error.
3.9. Каждая новая функция бизнес-логики сопровождается тестом (pytest / Vitest + React Testing Library).

## 4. Ограничения (строгие запреты)
4.1. ЗАПРЕЩЕНО использовать тип `any` в TypeScript и `# type: ignore` в Python без комментария с причиной.
4.2. ЗАПРЕЩЕНО хранить в коде секреты, ключи API, пароли и строки подключения — только переменные окружения; при добавлении новой переменной обнови `.env.example`.
4.3. ЗАПРЕЩЕНО собирать SQL-запросы конкатенацией или f-строками — только параметризованные запросы / ORM.
4.4. ЗАПРЕЩЕНО использовать `print()` в backend-коде — только `logging`.
4.5. ЗАПРЕЩЕНО добавлять новые зависимости без явного указания пакета, версии и причины в ответе.
4.6. ЗАПРЕЩЕНО формировать ответ ассистента пользователю без списка источников: если поиск не вернул фрагментов с релевантностью выше порога, сервис возвращает отказ (`refusal: true`), а не ответ модели.
4.7. ЗАПРЕЩЕНО логировать полный текст вопросов и претензий пользователей (персональные данные) — только идентификаторы, длину и служебные метрики.

## 5. Формат вывода
5.1. Перед кодом — краткий план изменений (2–5 пунктов) и список затрагиваемых файлов с путями.
5.2. Код выдаётся целыми файлами или явными фрагментами с указанием пути к файлу в заголовке блока кода.
5.3. Структура фичи на frontend: `src/features/<feature>/{components,hooks,api,types.ts}`; на backend: роут в `api/`, логика в `services/`, схемы в `schemas/`, тесты в `tests/` с зеркальной структурой.
5.4. В конце ответа — как проверить результат: команды запуска тестов и, если нужно, пример запроса (`curl`) или шаги ручной проверки в интерфейсе.
```
