## Тема магистерской

**«Разработка интеллектуального ассистента по защите прав потребителей на основе больших языковых моделей с применением RAG и дообучения»** (согласовывается с руководителем).

Ключевые решения, уже принятые:
- **Основа — RAG**: поиск по фрагментам нормативных документов + генерация ответа со ссылками на статьи. RAG даёт знания, дообучение (LoRA/QLoRA) учит поведению: формат ответа, ссылки, честный отказ.
- **Исследовательская часть** — сравнение конфигураций на одном тестовом наборе: модель без RAG; RAG с простым поиском; разная нарезка документов; улучшенный поиск (гибридный + реранкер); только дообучение; RAG + дообучение.
- **Метрики**: Recall@k и MRR для поиска; корректность, faithfulness, точность ссылок, доля корректных отказов для ответов; время ответа и память.
- **Модель локальная** (Ollama, 7–8 млрд параметров, например Qwen); дообучение на бесплатных GPU Kaggle/Colab, затем запуск локально (GGUF).
- **Документы базы**: Закон РФ № 2300-1 «О защите прав потребителей»; Правила продажи товаров (Пост. Правительства № 2463 от 31.12.2020); перечень технически сложных товаров (Пост. № 924 от 10.11.2011); Постановление Пленума ВС РФ № 17 от 28.06.2012; разъяснения Роспотребнадзора.
- **Данные**: готового русскоязычного QA-датасета по теме нет. Тестовый набор (150–200 вопросов) — генерация сильной облачной LLM по статьям + ручная проверка каждого вопроса + 30–50 реальных формулировок с форумов + 20–30 вопросов-ловушек. Обучающий набор (500–1500) — синтетика с выборочной проверкой, не пересекается с тестом. Генерировать не той моделью, которую тестируем.
- **Главная страховка от провала** — как можно раньше собрать минимальный рабочий RAG по одному закону.

### Что осталось сделать в ДЗ 2 и ДЗ 3

Места для заполнения в файлах помечены курсивом «_Заполнить_».

1. **`hw2/testing.md`** — один и тот же промпт в двух новых сессиях Claude Code: без `CLAUDE.md` (временно переименовать в `CLAUDE.md.off`) и с ним; вставить оба сырых ответа, отметить чек-лист из 12 пунктов, написать вывод. Можно прогнать через двух субагентов с чистым контекстом.
2. **`hw2/prompt_methodology.md`** — прогнать 4 промпта цепочки Chain-of-Thought (анализ структуры закона → парсер нарезки → схема БД и индексация → поиск и Recall@5) и записать результаты. Шаги 3–4 требуют PostgreSQL + pgvector и модели BGE-M3.
3. **`hw3/ui_concepts/`** — сгенерировать 3 концепции в v0.dev по промптам из `ui_description.md`, сохранить `concept_1.png` … `concept_3.png`, сверить описания. Это делаю я сам в браузере.
4. **`hw3/technical_specification.md`, раздел 7** — прогнать промпт проверки ТЗ, записать замечания и внести правки.
5. Сделать скриншоты работы агента для отчёта и загрузить всё в GitHub-репозиторий.
