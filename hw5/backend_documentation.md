# ДЗ 5. Локальный backend и PostgreSQL

В согласованном варианте PostgreSQL 16 с расширением pgvector работает в Docker на компьютере разработчика. Этот выбор позволяет использовать уже проиндексированный корпус и проверять RAG без передачи вопросов внешним сервисам. Для демонстрации нужно запустить весь стенд по [инструкции](../README.md).

## Путь запроса

Браузер → Vite (/api) → FastAPI → проверка сессии → BGE-M3 → поиск пяти ближайших фрагментов в PostgreSQL → фильтрация по косинусному сходству → Qwen через LLMClient → сохранение ответа и источников. По умолчанию граница сходства 0,5, допускаются значения строго выше порога. Это предварительная настройка для векторного поиска. При пустом контексте генерация пропускается. Если модель отказалась, пропустила ссылки или указала отсутствующий номер, сервис возвращает refusal=true. Проверка номера ссылки не гарантирует юридическую правильность вывода.

| Таблица | Назначение и связи |
|---|---|
| documents, chunks | Метаданные редакции и фрагменты закона с embedding размерности 1024. Каждый фрагмент относится к документу. |
| accounts | Уникальное нормализованное имя, UUID и хеш пароля scrypt с индивидуальной солью. |
| sessions | Хеш случайного токена, владелец и срок действия. Сессия действует семь дней, выход отзывает токен. |
| consultations | Владелец, вопрос, JSONB со снимком ответа и источников, необязательная оценка, время создания. |

Репозиторий ограничивает чтение, изменение и удаление по идентификатору из серверной сессии. Чужая и отсутствующая запись дают одинаковый ответ 404. Браузер хранит токен в HttpOnly SameSite=Strict cookie. CORS разрешает два адреса локального Vite. HTTP и cookie без Secure рассчитаны на loopback. При показе используйте вымышленные имена и вопросы. Полные тексты консультаций сохраняются в личной истории до удаления.

## Операции

| Метод и адрес | Ввод | Успех |
|---|---|---|
| POST /api/auth/register | username, password | 201, открывает сессию |
| POST /api/auth/login | username, password | 200, открывает сессию |
| GET /api/auth/me | Cookie | 200, имя пользователя |
| POST /api/auth/logout | Cookie | 204 |
| POST /api/consultations | question | 201, id, question, answer, helpful |
| GET /api/consultations | Cookie | 200, последние 100 записей от новых к старым |
| PATCH /api/consultations/{id} | helpful (boolean) | 204 |
| DELETE /api/consultations/{id} | Cookie | 204 |

Ошибки: 401 — нет действующей сессии или неверный пароль, 404 — запись недоступна, 409 — имя занято, 422 — неверный формат, 503 — Ollama недоступна. Отказ по содержанию приходит в обычном успешном ответе с пустым списком источников. Интерактивная спецификация доступна на http://127.0.0.1:8000/docs.

## Пример для PowerShell

```powershell
$api = 'http://127.0.0.1:8000/api'
$login = @{username=('student_' + (Get-Random));password=[guid]::NewGuid().ToString()} | ConvertTo-Json
Invoke-RestMethod "$api/auth/register" -Method Post -ContentType 'application/json' -Body $login -SessionVariable auth
$q = @{question='Купил телефон, через 10 дней сломался, могу вернуть деньги?'} | ConvertTo-Json
$result = Invoke-RestMethod "$api/consultations" -WebSession $auth -Method Post -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($q))
$result.answer
Invoke-RestMethod "$api/consultations/$($result.id)" -WebSession $auth -Method Patch -ContentType 'application/json' -Body '{"helpful":true}'
Invoke-RestMethod "$api/consultations" -WebSession $auth
Invoke-RestMethod "$api/consultations/$($result.id)" -WebSession $auth -Method Delete
```

## Разработка и проверка с AI

Агент изучил миграцию базы знаний, добавил вторую миграцию для личной истории и применил обе к рабочей и отдельной тестовой БД. Уже существующие 130 фрагментов сохранились. Для проверки разграничения доступа агент построил сценарий с двумя аккаунтами. Тест обращается к FastAPI через HTTPX и настоящему PostgreSQL, заменяя внешние вызовы модели предсказуемыми ответами. Сценарий охватывает создание, чтение, изменение, удаление, выход, повторный вход, попытку изменения чужой записи и ошибки валидации.

При первом прогоне pytest обнаружил конфликт имён двух тестовых модулей. Добавление файлов пакетов разделило пространства имён, после чего тесты прошли. Команды для повторения приведены в README. Регистрация в этом задании локальная. Поиск работает по имеющейся редакции закона от 28.12.2025, источник и дату следует учитывать при демонстрации.

### Сквозная проверка

В локальном Edge создан тестовый аккаунт и задан вопрос о компенсации морального вреда по статье 15. Интерфейс получил ответ Qwen с пятью доступными фрагментами базы. Через тот же интерфейс проверены оценка ответа, удаление консультации и выход. Этот прогон подтверждает работу цепочки от браузера до модели и БД. Юридическая точность текста требует отдельной экспертной оценки.

К существующему набору Python-пакетов добавлены FastAPI 0.128.0 для HTTP-маршрутов, валидации и OpenAPI и Uvicorn 0.40.0 для запуска ASGI-сервера.
